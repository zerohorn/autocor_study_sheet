Ansible for Network Configuration

▶

Core Model

  • Agentless — SSH push, nothing on device
  • Idempotent — safe to run many times
  • YAML playbooks describe desired state
  • gather_facts: false — required for network devices
  • Connection type: network_cli

State Options — Know Cold

  • merged — ADD without removing ✅ safe
  • replaced — replace specified resources only
  • overridden — replace ALL ⚠️ destructive
  • deleted — remove specified config
  • gathered — READ only, no changes
  • rendered — show config without applying

Key Modules

  • ios_vlans — VLAN config
  • ios_interfaces — interface settings
  • ios_l2_interfaces — trunk/access
  • ios_l3_interfaces — IP addresses
  • ios_ospfv2 — OSPF
  • ios_acls — ACL rules
  • ios_acl_interfaces — apply ACL to interface
  • ios_facts — asset management
  • ios_config — raw config + backup

Secrets + Handlers

  • ansible-vault create vault.yaml
  • ansible-vault edit vault.yaml
  • Reference: "{{ vault_device_password }}"
  • Run: --vault-password-file ~/.vault_pass
  • Handler: runs ONCE even if notified many times, only when task = changed

Workflow

  • terraform validate — syntax check (no connection)
  • terraform plan — preview: +add ~change -destroy

  • variable + sensitive = true — hides from logs
  • for_each / count — multiple resources

RESTCONF (RFC 8040) + YANG

▶

URL Pattern

https://device/restconf/data/
module:container/list=key

  • Always HTTPS port 443
  • Module prefix on top-level key required
  • Example: Cisco-IOS-XE-vlan:vlans/vlan=100
  • IETF: ietf-interfaces:interfaces

HTTP Methods

  • GET — read → 200
  • POST — create new → 201 (409 if exists)
  • PUT — full replace (wipes omitted fields)
  • PATCH — partial update (keeps other fields)
  • DELETE — remove → 204

Required Headers

  • Accept: application/yang-data+json
  • Content-Type: application/yang-data+json
  • Auth: HTTPBasicAuth (base64 user:pass)

pyang Symbols

  • +--rw — read-write → include in payload
  • +--ro — read-only → NEVER in config payload
  • * — list → JSON array
  • ? — optional, can omit
YANG Data Stores: running (active) · candidate (staging → commit) · startup (survives reboot)

REST APIs — Extended Attributes

▶

Pagination Patterns

  • Offset/Limit: ?limit=100&offset=0 → increment offset
  • Cursor: follow nextPage.token until null
  • Page Number: ?page=1&per_page=100
  • Stop when: len(page) < limit OR empty response

Auth Patterns

  • API Key: static header on every request
  • Token (Catalyst Center): POST creds → get token → reuse
  • OAuth 2.0: client_id + secret → access_token
  • Session: requests.Session() persists cookies

Rate Limiting

  • HTTP 429 = Too Many Requests
  • Read Retry-After header → wait → retry
  • Exponential backoff: 2^attempt seconds
  • Add random jitter to prevent thundering herd
  • Proactive: RateLimiter class before each call

Error Handling

  • 401 → expired token → refresh + retry
  • 403 → authenticated but forbidden
  • 404 → wrong URL or missing resource
  • 409 → exists → use PATCH not POST
  • 429 → rate limited → wait
  • JSONDecodeError → got HTML not JSON → check auth

Git Version Control Operations

▶

Merge Types

  • Fast-forward: main hasn't moved → slide pointer forward
  • --no-ff — force merge commit even if FF possible
  • Three-way: both branches moved → merge commit created
  • Squash: collapse many commits → one clean commit on main
  • After squash: git branch -D (capital D = force delete)

Conflict Markers

<<<<<<< HEAD ← your version your content here ======= ← divider their content here >>>>>>> feature/x ← incoming
  • Delete ALL marker lines → git add → git commit
  • Find remaining: grep -r "<<<<<" .
  • Abort entire merge: git merge --abort
  • Accept ALL theirs: git checkout --theirs .

Reset Modes (local only!)

  • --soft HEAD~1 — undo commit, keep staged
  • --mixed HEAD~1 — undo commit, keep files (default)
  • --hard HEAD~1 — undo commit, DELETE files ⚠️
  • Never reset pushed commits

Revert vs Reset

  • revert — adds NEW undo commit (safe for pushed)
  • reset — moves pointer back (local only)
  • Pushed? → git revert
  • Still local? → git reset fine
  • cherry-pick <hash> — one commit from another branch
  • Detached HEAD → git checkout -b new-branch

ScenarioAnswer

YAML/JSON Representation from YANG Models

▶

YANG → JSON Mapping Rules

  • module → prefix on outermost key
  • container → JSON object {}
  • list → JSON array [] (ALWAYS array)
  • leaf → key:value pair
  • leaf-list → array of same-type values

Type Cheatsheet

  • uint8/16/32 → number: "id": 100
  • string → quoted: "name": "Prod"
  • boolean → true/false (no quotes)
  • enumeration → quoted: "state": "active"
  • identityref → with prefix: "type": "iana-if-type:ethernetCsmacd"

pyang Symbols

  • +--rw — config, include in payload
  • +--ro — state, NEVER in config payload
  • * — list → JSON array
  • ? — optional, can omit
  • No ? — required (list key always required)

Common Mistakes

  • Missing module prefix on top-level key
  • List as object {} instead of array [{}]
  • Wrong types: "100" (string) vs 100 (number)
  • Including ro fields in config payload
  • Omitting list key leaf (always required)
VLAN JSON Example
// YANG: module → container vlans → list vlan { "Cisco-IOS-XE-vlan:vlans": { ← module:container "vlan": [ ← list = always array { "id": 100, "name": "Production", "state": "active" } ] } } // Same as YAML: Cisco-IOS-XE-vlan:vlans: vlan: - id: 100 name: Production state: active

Model-Driven Telemetry

▶

MDT vs SNMP

  • SNMP = pull (manager asks every ~5 min), text MIBs
  • MDT = push (device sends continuously), structured YANG
  • MDT = configurable interval in seconds
  • MDT = on-change for instant event notification

Subscription Types

  • Periodic: every N centiseconds regardless of change
  • → use for: counters, CPU, utilization
  • → config: update-policy periodic 1000 (=10s)
  • On-change: only when value actually changes
  • → use for: interface up/down, BGP/OSPF state
  • → config: update-policy on-change

Transport Protocols

  • gRPC — HTTP/2, port 57400/57500, most common
  • NETCONF — SSH, port 830, XML, dial-in only
  • gNMI — gRPC + OpenConfig standard
  • Dial-out — device calls collector (most common)
  • Dial-in — collector calls device

Full TIG Stack

  • Telegraf — collector (cisco_telemetry_mdt plugin)
  • InfluxDB — time-series database
  • Grafana — visualization + dashboards + alerting
  • GPB — binary, smallest, fastest (schema needed)
  • GPB-KV — binary, self-describing
  • JSON — human-readable, largest
Centiseconds math: 1000 = 10s · 3000 = 30s · 6000 = 60s  |  YANG path: /module:container/list/leaf · Secure with grpc-tls

Logging Strategy

▶

Syslog Severity Levels

  • 0 EMERGENCY · 1 ALERT · 2 CRITICAL
  • 3 ERROR ← task failed, API error
  • 4 WARNING ← retry, deprecated module
  • 5 NOTICE
  • 6 INFO ← task succeeded, config applied
  • 7 DEBUG ← all detail, raw responses
  • Lower number = higher severity

Python Logging Architecture

  • Logger → Handler → Formatter
  • getLogger('name') — singleton everywhere
  • setLevel(DEBUG) — gate (lower # = captures more)
  • SysLogHandler(address=('ip', 514))
  • UDP default (fire-and-forget)
  • Multiple handlers = logs to all simultaneously
  • Use %s not f-strings (lazy evaluation)

Syslog vs Webhook

  • Syslog — passive DVR, stores everything
  • → UDP 514 default · TCP for reliable delivery
  • → long-term storage, audit trail
  • Webhook — active doorbell, triggers actions
  • → HTTP POST to Webex/Slack/PagerDuty
  • → real-time alerting on failures

Best Practices

  • Production: set level INFO
  • Debug/troubleshoot: set level DEBUG
  • CI/CD: ERRORs → webhook, all → syslog
  • Never log credentials or tokens ❌
  • TCP for reliable syslog: socktype=socket.SOCK_STREAM

TLS Certificates

▶

Key Concepts

  • Private key 🗝️ — never leaves server
  • Public key 🏠 — share freely, embedded in cert
  • CSR 📋 — passport application (sent to CA)
  • Certificate 🪪 — signed passport (CA stamped)
  • CA 🏛️ — trusted signing authority

Process Flow

  • Gen key: openssl genrsa -out server.key 2048
  • Create CSR: openssl req -new -key server.key -out server.csr
  • CA signs CSR → returns server.crt
  • Deploy: key + cert + CA chain
  • Trust chain: cert → intermediate → root → ✅

Python Usage

  • verify='/path/to/ca-chain.crt' — use your CA
  • verify=False — DEV ONLY, NEVER production ❌
  • cert=('client.crt','client.key') — mutual TLS
  • Browser uses system trust store; Python uses its own

Let's Encrypt / ACME

  • Free, automated, 90-day certs
  • Domain validated via HTTP port 80 (must be open)
  • Alt: DNS-01 challenge (no port 80 needed)
  • Air-gapped networks → use internal CA instead

4.3

MCP Server with Python FastMCP

▶

What MCP Does

  • Bridges AI agents to real network data and actions
  • User → AI → MCP Client → MCP Server → Network
  • Tools — functions AI can call
  • Resources — data AI can read (URI-addressed)
  • Prompts — reusable instruction templates

FastMCP Pattern

  • mcp = FastMCP(name, instructions)
  • @mcp.tool() — register a callable tool
  • @mcp.resource("uri") — register a resource
  • @mcp.prompt() — register a prompt template
  • mcp.run() — start with stdio (default)
  • mcp.run(transport="sse", host=..., port=...) — remote

Transport Types

  • stdio — local, same machine, dev/testing, 1 client
  • SSE — remote, HTTP, multiple clients, production

Tool Design Rules

  • Type hints REQUIRED — define the schema AI uses
  • Docstring REQUIRED — AI reads to decide when/how to call
  • Secrets in env vars (never in code)
  • verify= CA cert (never False)
  • Validate inputs — return error dict if invalid
from fastmcp import FastMCP import os, requests mcp = FastMCP("Network Tools") @mcp.tool() def get_vlans(device_ip: str) -> dict: """Get all VLANs on a Cisco IOS XE switch. Args: device_ip - management IP of target switch Returns: dict with VLAN list""" url = f"https://{device_ip}/restconf/data/Cisco-IOS-XE-vlan:vlans" return requests.get(url, auth=(os.getenv("DEVICE_USER"), os.getenv("DEVICE_PASS")), headers={"Accept": "application/yang-data+json"}, verify=os.getenv("CA_CERT_PATH")).json() if __name__ == "__main__": mcp.run(transport="sse", host="0.0.0.0", port=8000)

4.4

Conversational Agent with LLMs

▶

ReAct Loop Pattern

  • Thought → "I need to check OSPF neighbors"
  • Action → call get_ospf_neighbors()
  • Observation → tool result returned
  • Repeat until enough info to answer
  • Final answer → stop_reason = "end_turn"

Agent Loop Logic

  • stop_reason == "tool_use":
  • → extract tool name + input from content block
  • → execute the tool call
  • → append result to messages as tool_result
  • → call API again (loop continues)
  • stop_reason == "end_turn":
  • → extract text from content, return as answer

3 Key Components

  • System prompt — personality, constraints, what NOT to do
  • Messages list — FULL conversation history each call
  • Tools list — schema for what agent can call
  • All three passed to messages.create()
  • max_iterations — prevents infinite loops

LangChain (4.4 Extension)

  • Framework that wraps the manual agent pattern
  • @tool decorator — registers Python function as tool
  • AgentExecutor — handles ReAct loop automatically
  • ChatAnthropic() — LLM abstraction layer
  • agent_scratchpad — ReAct workspace in prompt
  • max_iterations — prevents infinite loops
  • Provider abstraction — swap LLM with one line
# Core agent loop skeleton iterations = 0 while iterations < MAX_ITERATIONS: response = client.messages.create( model="claude-sonnet-4-6", system=SYSTEM_PROMPT, tools=NETWORK_TOOLS, messages=messages ) if response.stop_reason == "end_turn": return response.content[0].text # done — final answer if response.stop_reason == "tool_use": messages.append({"role": "assistant", "content": response.content}) # ... execute tool, append tool_result to messages ... iterations += 1 # loop continues
